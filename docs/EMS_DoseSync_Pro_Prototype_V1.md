# 1. 產品定位

## 1.1 產品目的

EMS DoseSync Pro 是一款用於院前 OHCA 現場的給藥與事件時間同步輔助裝置。

主要目標：

- 協助 EMT / ALS 接手人員掌握 EPI 給藥 4 分鐘節奏
- 紀錄本機 EPI、電擊、Amiodarone 事件時間戳
- 支援接手前與純補登事件
- 降低高壓現場記錄負擔
- 案件結束後提供完整案件總覽
- 可將單一案件同步至手機 App，輔助 EMT 登打救護紀錄表
- 提供獨立 6秒通氣節奏模式
- 提供 Training 模式作為訓練與教學用途

# 4. 硬體按鍵配置與基本邏輯

## 4.1 主要按鍵

| 按鍵 | 實體外觀標示 | 功能定位 |
|---|---|---|
| 主按鍵 | 大型主按鍵 | 選單確認、開始、結束確認、消音 |
| 返回鍵 | 返回圖示 / 返回鍵 | 返回、取消、開啟快速功能選單 |
| 上鍵 | 上方向圖示 | 選單上移 / 音量增加 |
| 下鍵 | 下方向圖示 | 選單下移 / 音量降低 |
| EPI 鍵 | 針筒圖案 | 即時 EPI 事件入口 / 長按進入 EPI / 藥物選單 |
| 電擊鍵 | 閃電圖案 | 即時電擊事件入口 / 長按進入電擊補登選單 |
| Power 鍵 | 電源圖示 | 開關機 |
| 錄音鍵 | 錄音圖示位置預留 | V1 保留外觀位置，但不啟用錄音功能 |

## 4.1.1 按鍵圖示標示規則

- EPI 實體鍵外觀標示需使用針筒圖案。
- 電擊實體鍵外觀標示需使用閃電圖案。
- 電擊鍵表面不得使用 `Shock` 字樣。
- EPI 鍵表面不以 `EPI` 文字作為主要標示。
- 裝置畫面、案件總覽、Timeline 與 App 內仍使用事件名稱 `EPI` 與 `電擊`。
- 韌體內部工程命名可維持 `epi_button`、`shock_button` 等命名，但所有使用者介面不得顯示 `Shock`，需顯示中文「電擊」。
- 若工程打樣階段需暫時使用貼紙標示，仍應以針筒圖案與閃電圖案為準。

# 5. OHCA 案件模式

## 5.1 OHCA 啟動

主功能表預設游標停在 OHCA 案件。

```text
EMS DoseSync Pro

> OHCA 案件
  6秒通氣節奏
  訓練模式
  歷史紀錄
  系統設定
```

短按主按鍵開始 OHCA 案件。

---

## 5.2 案件開始提示

開始後顯示 1 秒：

```text
案件開始
OHCA
```

接著進入：

```text
待本機 EPI
EPI 0｜電擊 0
```

---

## 5.3 重要原則

案件開始不等於 EPI 倒數開始。

EPI 4 分鐘倒數只能由「本機即時 EPI 二段確認」成立後啟動。

# 6. EPI 邏輯

## 6.1 第一次本機 EPI 前

畫面顯示：

```text
待本機 EPI
EPI 0｜電擊 0
```

此狀態下允許：

- 即時 EPI
- 即時電擊
- 接手前補登
- 純補登
- Amiodarone 紀錄

但在第一筆本機 EPI 成立前，不啟動 4 分鐘倒數。

---

## 6.2 即時 EPI 操作

```text
按 EPI
→ 確認已給 EPI？
→ 再按 EPI
→ 建立 EPI 時間戳
→ EPI 次數 +1
→ 啟動 / 重啟 4 分鐘倒數
```

確認畫面：

```text
確認已給 EPI？
再按 EPI 確認
返回取消
```

---

## 6.3 EPI 成功提示

EPI 成立後顯示 1 秒：

```text
EPI 已紀錄
重新倒數 4 分鐘
```

接著進入倒數主畫面。

---

## 6.4 EPI 倒數畫面

正常倒數：

```text
03:58
下次給藥
EPI 1｜電擊 1
```

剩 1 分鐘：

```text
00:59
請準備給藥
EPI 1｜電擊 1
```

到期：

```text
04:00
請給藥
EPI 1｜電擊 1
```

超時後顯示自上一筆本機 EPI 起算的累計經過時間：

```text
05:43
請給藥
EPI 1｜電擊 1
```

---

## 6.5 EPI 時間顯示規則

| 狀態 | 顯示 |
|---|---|
| 4 分鐘內 | 倒數剩餘時間 |
| 剩 1 分鐘 | 請準備給藥 |
| 到 4 分鐘 | 請給藥 |
| 超過 4 分鐘 | 顯示自上一筆本機 EPI 起算的總經過時間 |

---

## 6.6 EPI 預警與警報

| 狀態 | 聲音 | LED |
|---|---|---|
| 正常倒數 | 無 | 正常狀態 |
| 剩 1 分鐘 | 每 15 秒短提示音 | 黃燈慢閃 |
| 到期 0～5 秒 | 高優先警報連續 5 秒 | 紅燈快閃 |
| 超過 5 秒仍未確認 | 每 15 秒短提醒 | 紅燈慢閃 |

---

## 6.7 EPI 到期後按鍵行為

| 按鍵 | 功能 |
|---|---|
| EPI 鍵 | 消音 + 進入 EPI 確認畫面 |
| 再按 EPI | 建立新 EPI 時間戳，重啟 4 分鐘 |
| 主按鍵 | 只消音，不進入確認，不建立紀錄 |
| 返回鍵 | 取消確認，回到請給藥畫面 |
| 電擊鍵 | 可照常二段確認紀錄電擊 |

---

## 6.8 EPI 確認取消後

若在 EPI 確認畫面按返回鍵：

```text
返回取消
→ 回到請給藥畫面
→ 不立刻恢復連續警報
→ 15 秒未確認則短促提醒一次
→ 之後每 15 秒提醒一次
```

# 8. Amiodarone 邏輯

## 8.1 Amiodarone 定位

Amiodarone 不設獨立實體按鍵。

Amiodarone 屬於「EPI / 藥物選單」內的選單事件，不屬於即時 EPI 事件。

因此 Amiodarone 的最終確認使用主按鍵，不使用針筒圖案鍵，避免與 EPI 給藥確認混淆。

---

## 8.2 Amiodarone 入口

Amiodarone 由長按針筒圖案鍵進入藥物選單後選取：

```text
長按針筒圖案鍵
→ EPI / 藥物選單
→ Amiodarone
```

---

## 8.3 Amiodarone 確認畫面

Amiodarone 選取後，確認畫面需放大提示文字。

建議畫面：

```text
確認 Amiodarone？

主鍵確認
返回取消
```

畫面設計原則：

- 「確認 Amiodarone？」需使用大字顯示。
- 「主鍵確認」需清楚顯示，建議使用大字或反白。
- 「返回取消」可用較小字顯示。
- 畫面不得顯示「再按針筒鍵確認」。
- 針筒圖案鍵不得作為 Amiodarone 的最終確認鍵。

---

## 8.4 Amiodarone 操作流程

```text
長按針筒圖案鍵
→ EPI / 藥物選單
→ Amiodarone
→ 確認 Amiodarone？
→ 主鍵確認
→ 建立 Amiodarone 時間戳
→ 顯示 Amiodarone 已紀錄
→ 回原 OHCA / Training 畫面
```

---

## 8.5 Amiodarone 成功提示

```text
Amiodarone 已紀錄
```

顯示 1 秒後回到原狀態。

---

## 8.6 Amiodarone 規則

Amiodarone：

- 建立本機時間戳
- 寫入 Timeline
- 更新藥物紀錄
- 不影響 EPI 次數
- 不啟動 EPI 倒數
- 不重啟 EPI 倒數
- 不解除 EPI 超時狀態
- 不使用針筒圖案鍵作為最終確認
- 不得被短按針筒圖案鍵直接觸發

---

## 8.7 與 EPI 的操作差異

| 項目 | EPI | Amiodarone |
|---|---|---|
| 入口 | 短按針筒圖案鍵 | 長按針筒圖案鍵 → EPI / 藥物選單 |
| 最終確認 | 再按針筒圖案鍵 | 主按鍵 |
| 是否建立時間戳 | 是 | 是 |
| 是否寫入 Timeline | 是 | 是 |
| 是否影響 EPI 次數 | 是 | 否 |
| 是否啟動 / 重啟 EPI 倒數 | 是 | 否 |
| 是否解除 EPI 超時 | 是，因新 EPI 成立而重啟倒數 | 否 |

# 8A. 藥物給藥功能總定義

## 8A.1 藥物給藥入口原則

EMS DoseSync Pro Prototype V1 中，針筒圖案按鍵為裝置內唯一給藥功能入口。

針筒圖案按鍵負責進入與藥物給藥相關的操作，不另設其他藥物實體按鍵。

---

## 8A.2 EPI 給藥操作定義

EPI 是 OHCA 流程中具有固定循環倒數需求的藥物。

因此，只有 EPI 採用全程由針筒圖案鍵操作與確認的邏輯：

```text
短按針筒圖案鍵
→ 確認已給 EPI？
→ 再按針筒圖案鍵確認
→ 建立 EPI 時間戳
→ 啟動 / 重啟 EPI 倒數
```

EPI 的特殊性：

- EPI 有 4 分鐘循環倒數。
- EPI 是主流程高頻事件。
- EPI 二段確認成立後會啟動或重啟倒數。
- EPI 是唯一會影響 EPI 倒數迴圈的藥物事件。

---

## 8A.3 Amiodarone 給藥操作定義

Amiodarone 不設獨立實體按鍵。

Amiodarone 由長按針筒圖案鍵喚出藥物選單後選取。

```text
長按針筒圖案鍵
→ EPI / 藥物選單
→ Amiodarone
→ 確認 Amiodarone？
→ 主鍵確認
→ 建立 Amiodarone 時間戳
```

Amiodarone 屬於藥物選單事件，不屬於即時 EPI 事件。

Amiodarone 最終確認使用主按鍵，不使用針筒圖案鍵。

---

## 8A.4 其他藥物功能定位

除 EPI 與 Amiodarone 外，其他救護現場可能使用的藥物，不納入 Prototype V1 必做範圍。

原因：

- 會增加操作複雜度。
- 不同情境藥物差異大。
- 不同 protocol 版本可能更新。
- V1 應先聚焦 OHCA 給藥節奏與事件紀錄。
- 過多藥物選單可能增加現場誤觸或選錯風險。

---

## 8A.5 未來擴充：其他藥物紀錄功能

未來版本可考慮新增「其他藥物紀錄」功能。

可放在：

```text
長按針筒圖案鍵
→ 藥物紀錄
→ 選擇藥物
```

或於 App / 電腦端提供藥物清單設定。

未來可內建：

- 新北 protocol 內常用藥物
- OHCA 相關藥物
- ALS 現場可能使用藥物
- 幾組自定義藥物欄位

---

## 8A.6 未來其他藥物紀錄原則

其他藥物若未來納入，建議一律採用選單事件邏輯：

```text
選擇藥物
→ 確認藥物名稱？
→ 主鍵確認
→ 建立時間戳
→ 寫入 Timeline
```

其他藥物原則上：

- 不使用針筒圖案鍵作為最終確認。
- 不啟動 EPI 倒數。
- 不重啟 EPI 倒數。
- 不解除 EPI 超時狀態。
- 僅建立藥物事件時間戳。
- 寫入案件 Timeline。
- 可列入 App 完整總覽與 Timeline。

---

## 8A.7 藥物操作邏輯總表

| 藥物 / 功能 | 入口 | 最終確認鍵 | 是否建立時間戳 | 是否影響 EPI 倒數 | V1 狀態 |
|---|---|---|---|---|---|
| EPI | 短按針筒圖案鍵 | 針筒圖案鍵 | 是 | 是，啟動 / 重啟倒數 | V1 必做 |
| 補登 EPI | 長按針筒圖案鍵 → 補登 EPI | 主按鍵 | 否，補登時間欄為 `-` | 否 | V1 必做 |
| Amiodarone | 長按針筒圖案鍵 → Amiodarone | 主按鍵 | 是 | 否 | V1 必做 |
| 其他藥物 | 未來藥物選單 | 主按鍵 | 是 | 否 | 未來擴充 |

---

## 8A.8 操作原則

本裝置藥物操作遵循：

```text
針筒圖案鍵 = 藥物功能唯一入口
EPI = 唯一使用針筒圖案鍵完成即時二段確認的藥物
其他藥物 = 選單選取後由主按鍵確認
返回鍵 = 取消
```

# 9. 補登邏輯

## 9.1 補登來源分類

補登來源統一為：

```text
接手前
純補登
```

不得使用「漏記補登」。

---

## 9.2 EPI 補登入口

長按 EPI：

```text
EPI / 藥物選單

> 補登 EPI
  Amiodarone
```

---

## 9.3 電擊補登入口

長按電擊鍵：

```text
電擊補登

> 接手前電擊
  純補登電擊
```

---

## 9.4 補登確認方式

補登屬於選單資料確認，最終確認由主按鍵完成。

確認畫面：

```text
確認補登？
接手前 EPI ×2
成立後不可撤銷
```

或：

```text
確認補登？
純補登電擊 ×1
成立後不可撤銷
```

---

## 9.5 補登成功提示

顯示補登類型 + 事件類型 + 次數。

```text
接手前 EPI ×2
補登成功
```

```text
純補登電擊 ×1
補登成功
```

顯示 2 秒。

---

## 9.6 補登次數

| 補登項目 | 可選次數 |
|---|---|
| 接手前 EPI | 1～5 |
| 純補登 EPI | 1～3 |
| 接手前電擊 | 1～5 |
| 純補登電擊 | 1～3 |

---

## 9.7 補登規則

補登成立後：

- 更新總次數
- 寫入案件事件紀錄
- 不建立本機即時時間戳
- 不輸入實際發生時間
- 不啟動 EPI 倒數
- 不重啟 EPI 倒數

# 14. OHCA 中開啟 6秒通氣恆常顯示

## 14.1 功能定位

EMS DoseSync Pro 保留兩種 6秒通氣使用情境：

| 使用情境 | 定義 |
|---|---|
| 主功能表「6秒通氣節奏」 | 獨立即時節奏工具 |
| OHCA 案件中開啟 6秒通氣 | OHCA 主畫面內的輔助子計時器 |

OHCA 案件中若開啟 6秒通氣，該功能不再作為獨立切換畫面，而是固定顯示於 OHCA 主畫面內。

OHCA 內 6秒通氣應視為 OHCA 主流程的輔助顯示區塊，而不是另一個模式頁面。

---

## 14.2 OHCA 內 6秒通氣顯示方式

OHCA 主畫面需同時顯示：

- OHCA 狀態
- EPI 倒數 / 超時狀態
- 給藥提示文字
- EPI 次數
- 電擊次數
- 6秒通氣輔助區塊

畫面範例：

```text
OHCA中

03:28
下次給藥

EPI 1｜電擊 1

6秒給氣｜已開啟
4
```

---

## 14.3 單秒數視窗顯示

OHCA 內 6秒通氣顯示方式採用「單秒數視窗」。

不顯示完整：

```text
1 2 3 4 5 6
```

而是只顯示目前秒數：

```text
4
```

目前秒數每秒更新一次，循環規則如下：

```text
1 → 2 → 3 → 4 → 5 → 6 → 1
```

---

## 14.4 秒數提示規則

OHCA 內 6秒通氣的秒數提示規則需與主功能表內的獨立 6秒通氣節奏功能一致。

每一輪的第 1 秒需要比較明顯，作為通氣提示點。

### 第 1 秒

第 1 秒需觸發明顯提示：

- 畫面反紅
- 加強提示音
- 紅燈閃爍

畫面範例：

```text
OHCA中

03:28
下次給藥

EPI 1｜電擊 1

6秒給氣｜已開啟
1
```

第 1 秒顯示時，6秒通氣區塊或秒數視窗需以反紅方式提示。

### 第 2～6 秒

第 2～6 秒為一般節奏提示：

- 每秒短提示音
- LED 不閃爍
- 畫面正常顯示
- 秒數視窗依序顯示 2、3、4、5、6

範例：

```text
6秒給氣｜已開啟
4
```

---

## 14.5 音量與靜音規則

OHCA 內 6秒通氣使用「通氣音量」設定。

通氣音量範圍：

```text
0～5
```

| 等級 | 意義 |
|---|---|
| 0 | 靜音 |
| 1～5 | 通氣節奏提示音量 |

當通氣音量為 0 時：

- 第 1 秒加強提示音關閉
- 第 2～6 秒每秒短提示音關閉
- 第 1 秒畫面反紅仍保留
- 第 1 秒紅燈閃爍仍保留
- 秒數視窗仍正常顯示 1～6

---

## 14.6 與 OHCA 主流程的關係

OHCA 內 6秒通氣為輔助子計時器，不得影響 OHCA 主流程。

以下事件發生後，6秒通氣仍應維持開啟與顯示：

- EPI 給藥確認
- 電擊確認
- Amiodarone 確認
- 補登完成
- EPI 倒數重啟
- EPI 到期警報
- EPI 超時狀態

EPI 給藥完成後，畫面回到 OHCA 主畫面時，6秒通氣區塊不得消失。

電擊、Amiodarone 或補登完成後，畫面回到 OHCA 主畫面時，6秒通氣區塊也不得消失。

---

## 14.7 EPI 到期優先權

EPI 到期仍為 OHCA 高優先事件。

當 EPI 到期時：

- OHCA 主畫面需顯示「請給藥」
- EPI 高優先警報需啟動
- 6秒通氣秒數視窗仍可保留在畫面下方
- 6秒通氣不得蓋過 EPI 到期警報
- 6秒通氣不得阻止 EPI 給藥確認

EPI 到期畫面範例：

```text
OHCA中

04:00
請給藥

EPI 1｜電擊 1

6秒給氣｜已開啟
5
```

---

## 14.8 開啟與關閉

OHCA 中可透過快速功能開啟或關閉 6秒通氣。

未開啟時：

```text
快速功能

> 開啟6秒給氣提示
  案件簡版總覽
  返回 OHCA
```

已開啟時：

```text
快速功能

> 關閉6秒給氣提示
  案件簡版總覽
  返回 OHCA
```

開啟後，6秒通氣區塊固定顯示於 OHCA 主畫面中，直到手動關閉或案件結束。

---

## 14.9 案件結束規則

OHCA 案件結束後，OHCA 內 6秒通氣提示自動停止。

6秒通氣不寫入 Timeline。

6秒通氣不列入案件事件紀錄。

6秒通氣不影響 EPI、電擊、Amiodarone 或補登資料。

---

## 14.10 與獨立 6秒通氣功能的一致性

OHCA 內 6秒通氣與主功能表內獨立 6秒通氣節奏需共用相同秒數提示規則：

| 項目 | 獨立 6秒通氣 | OHCA 內 6秒通氣 |
|---|---|---|
| 秒數循環 | 1～6 | 1～6 |
| 顯示方式 | 單一目前秒數 | 單秒數視窗 |
| 第 1 秒畫面反紅 | 是 | 是 |
| 第 1 秒加強提示音 | 是 | 是 |
| 第 1 秒紅燈閃爍 | 是 | 是 |
| 第 2～6 秒每秒短提示音 | 是 | 是 |
| 第 2～6 秒 LED 閃爍 | 否 | 否 |
| 通氣音量 | 0～5 | 0～5 |
| 靜音時視覺提示 | 保留 | 保留 |

---

## 14.11 定案

- 主功能表內獨立 6秒通氣節奏功能保留。
- OHCA 內開啟 6秒通氣時，改為 OHCA 主畫面內的恆常顯示輔助區塊。
- OHCA 內 6秒通氣採單秒數視窗顯示，不顯示 1～6 整排數字。
- OHCA 內 6秒通氣秒數循環規則與獨立功能一致，為 1 → 2 → 3 → 4 → 5 → 6 → 1。
- 每一輪第 1 秒需作為主要通氣提示點。
- 第 1 秒需畫面反紅、加強提示音、紅燈閃爍。
- 第 2～6 秒需每秒短提示音，LED 不閃爍。
- OHCA 內 6秒通氣不影響 EPI 倒數、電擊、Amiodarone 或補登邏輯。
- EPI 給藥、電擊、Amiodarone、補登完成後，6秒通氣區塊仍需維持顯示。
- OHCA 案件結束後，OHCA 內 6秒通氣自動停止。
- OHCA 內 6秒通氣不寫入 Timeline，不列入案件事件紀錄。

# 15. Training 模式

## 15.1 Training 核心定義

Training 模式需定義為：

> **Training 模式 = OHCA 模式的訓練版本。**

Training 模式不應另寫成獨立簡化流程，也不應省略 OHCA 核心事件邏輯。

Training 與 OHCA 的主要差異只有：

- EPI 倒數時間可調整
- 畫面全程標示「訓練模式」
- 案件總覽標示為「案件總覽｜Training」
- Timeline 標示為「事件時間軸｜Training」
- 歷史紀錄歸類到 Training 紀錄
- Training 歷史保存上限為 20 筆
- Training 紀錄可由裝置端手動刪除
- OHCA 正式案件不可由裝置端手動刪除

---

## 15.2 Training 與 OHCA 的差異表

| 項目 | OHCA 正式案件 | Training 模式 |
|---|---|---|
| EPI 倒數時間 | 固定 4 分鐘 | 可選 30秒 / 1分鐘 / 4分鐘 |
| 畫面標示 | OHCA | 訓練模式 |
| 案件總覽 | 案件總覽｜OHCA | 案件總覽｜Training |
| Timeline | 事件時間軸 | 事件時間軸｜Training |
| 歷史分類 | OHCA 案件 | Training 紀錄 |
| 保存上限 | 50 筆 | 20 筆 |
| 裝置端刪除 | 不可 | 可刪除 |
| App 同步 | 可 | 可，但標示 Training |

---

## 15.3 Training 入口與倒數時間選擇

主功能表選擇：

```text
訓練模式
```

進入後先顯示：

```text
訓練倒數

> 30秒
  1分鐘
  4分鐘
```

操作：

| 按鍵 | 功能 |
|---|---|
| 上 / 下鍵 | 切換倒數時間 |
| 主按鍵 | 確認選擇 |
| 返回鍵 | 返回主功能表 |

倒數時間：

| 選項 | 實際倒數時間 |
|---|---:|
| 30秒 | 30 秒 |
| 1分鐘 | 60 秒 |
| 4分鐘 | 240 秒 |

此倒數時間只取代 OHCA 原本固定 4 分鐘的 EPI 倒數週期，其他事件邏輯不得改變。

---

## 15.4 Training 初始狀態

選定倒數時間後，進入 Training 初始狀態：

```text
訓練模式
待本機 EPI
EPI 0｜電擊 0
```

此時不啟動倒數。

Training 與 OHCA 相同：

> 案件開始不等於 EPI 倒數開始。

只有第一筆「本機 EPI 二段確認」成立後，才啟動 Training 倒數。

---

## 15.5 Training EPI 邏輯

Training 中即時 EPI 與 OHCA 相同，只是倒數長度使用使用者選擇的 Training 倒數時間。

```text

→ 確認已給 EPI？

→ 建立 Training 本機 EPI 時間戳
→ EPI 次數 +1
→ 啟動 / 重啟所選 Training 倒數
```

EPI 成功提示：

```text

重新倒數
```

顯示 1 秒後回 Training 倒數畫面。

## 15.11 Training 結束前檢查

```text
  返回訓練
```

# 18. 資料保存與 Type-C 管理

## 18.1 裝置端保存

| 類型 | 保存上限 |
|---|---|
| OHCA 正式案件 | 最近 50 筆 |
| Training 紀錄 | 最近 20 筆 |

---

## 18.2 裝置端刪除規則

OHCA 正式案件：

- 裝置本體不提供手動刪除功能
- 只能依 50 筆上限自動覆蓋
- 若需提前清除，需透過 Type-C 電腦端管理工具

Training 紀錄：

- 裝置本體可手動刪除
- 僅限 Training 紀錄
- 刪除前需二次確認
- 刪除後不可復原
- 不影響 OHCA 正式案件
- 不回寫 App 端已同步資料

---

## 18.3 Type-C 電腦端管理

若需提前清除資料，只能透過 Type-C 電腦端管理工具。

流程：

```text
Type-C 連接電腦
→ EMS DoseSync 管理工具
→ 匯出 / 備份
→ 二次確認
→ 清除資料
```

清除前需提示備份並二次確認。

---

## 18.4 Type-C 連線頁

系統設定內 Type-C 連線頁只顯示狀態，不提供手動模式切換。

```text
Type-C 連線

狀態：未連線
用途：資料備援 / 電腦管理
```

連線後：

```text
Type-C 連線

狀態：已連線
模式：電腦管理
```

## 19.2 裝置名稱

每台裝置可自定義名稱。

裝置名稱由手機 App 輸入後寫入裝置。

裝置端不負責中文輸入。

首次使用：


未設定時使用：

```text
未命名
```

案件進行中不可修改裝置名稱。

裝置名稱會隨案件同步至 App。

---

## 19.3 螢幕亮度

螢幕亮度採 1～5 段。

```text
螢幕亮度：3/5
```

規則：

- 最低 1
- 不提供完全關閉螢幕
- 預設 3/5
- 需記憶，下次開機沿用上次設定
- 實際亮度值由 Prototype 測試後由工程師校正

---

## 19.4 系統音量

系統音量採 1～5 段。

```text
系統音量：3/5
```

系統音量控制：

- OHCA 警報音
- EPI 預警音
- 成功音
- 錯誤音
- 案件完成音

系統音量不可靜音，最低為 1。

實際分貝由工程師於 Prototype 測試後校正。

---

## 19.5 通氣音量

通氣音量採 0～5 段。

```text
通氣音量：3/5
```

0 = 靜音。

控制：

- 6秒通氣節奏每秒提示音
- 第 1 秒加強提示音

通氣音量需記憶。

---

## 19.6 恢復預設值

系統設定提供恢復預設值。


恢復內容：

- 螢幕亮度回 3/5
- 系統音量回預設值
- 通氣音量回預設值

不清除：

- 裝置名稱
- OHCA 案件
- Training 紀錄
- App 同步狀態

# 22. Prototype V1 測試情境

## 22.1 OHCA 基本流程測試

- 開機
- 進入 OHCA
- 顯示案件開始
- 進入待本機 EPI
- 第一次 EPI 二段確認
- 啟動 4 分鐘倒數
- 到期警報
- 第二次 EPI 二段確認
- 案件結束
- 案件總覽

---

## 22.2 電擊測試

- 第一次本機 EPI 前紀錄電擊
- EPI 倒數中紀錄電擊
- EPI 超時中紀錄電擊
- OHCA 中 6秒通氣節奏畫面紀錄電擊

---

## 22.3 Amiodarone 測試

- 第一次本機 EPI 前紀錄 Amiodarone
- EPI 倒數中紀錄 Amiodarone
- EPI 超時中紀錄 Amiodarone

---

## 22.4 補登測試

- 接手前 EPI ×2
- 接手前電擊 ×2
- 純補登 EPI ×1
- 純補登電擊 ×1
- EPI 超時中補登
- 結束前檢查中補登

---

## 22.5 6秒通氣節奏測試

- 獨立進入
- 1～6 循環
- 第 1 秒反紅
- 每秒提示音
- 通氣音量調整
- 靜音
- 結束確認
- 低電量提醒
- 邊充邊用

---

## 22.6 OHCA 中開啟 6秒通氣恆常顯示測試

- 從快速功能開啟 6秒給氣提示
- OHCA 主畫面下方固定顯示 6秒給氣區塊
- 6秒給氣採單秒數視窗顯示
- 秒數依序循環 1 → 2 → 3 → 4 → 5 → 6 → 1
- 第 1 秒畫面反紅、加強提示音、紅燈閃爍
- 第 2～6 秒每秒短提示音，LED 不閃爍
- EPI 給藥確認後，6秒給氣區塊仍維持顯示

# 23. 工程注意事項

## 23.1 最高優先原則

OHCA EPI 到期是高優先事件。

若 OHCA 中已開啟 6秒通氣恆常顯示，EPI 到期時必須以 OHCA 警報為最高優先顯示「請給藥」。6秒通氣可保留於畫面下方輔助區塊，但不得蓋過或阻礙 EPI 警報與 EPI 給藥確認。

---

## 23.2 EPI 倒數啟動原則

只有本機 EPI 二段確認成立，才可啟動或重啟 4 分鐘倒數。

以下事件不得啟動或重啟 EPI 倒數：

- 電擊
- Amiodarone
- 接手前 EPI
- 純補登 EPI
- 接手前電擊
- 純補登電擊

---

## 23.3 補登資料可信度

補登事件不具精準實際發生時間。

補登事件應與本機即時紀錄明確區分。

---

## 23.4 App 同步資料安全

同步資料需以 Case ID 去重。

同步中斷重試時，重新傳送整筆案件，不做片段接續。

App 端已有同 Case ID 時覆蓋 / 更新，不新增第二筆。

---

## 23.5 裝置端資料保留

App 同步不刪除裝置端原始資料。

裝置資料依保存上限自動覆蓋。

提前清除資料只能透過 Type-C 電腦端管理工具。

---

## 23.6 音量注意

系統音量不可靜音。

通氣音量可靜音。

各音量等級實際分貝由工程師於 Prototype 測試後校正。

---

## 23.7 Training 實作注意

Training 不應另寫成獨立簡化流程。

Training 應以 OHCA 核心狀態機為基礎，僅用參數區分：

```text
case_mode = Training
epi_interval_seconds = 30 / 60 / 240
history_limit = 20
allow_device_delete = true
show_training_label = true
```

OHCA 正式案件則為：

```text
case_mode = OHCA
epi_interval_seconds = 240
history_limit = 50
allow_device_delete = false
show_training_label = false
```

---

## 23.8 按鍵圖示注意

EPI 實體鍵外觀標示為針筒圖案。

電擊實體鍵外觀標示為閃電圖案。

使用者介面不得顯示 `Shock`，需統一顯示中文「電擊」。

韌體內部工程命名可維持 `shock_button`，但 UI / App / Timeline / 案件總覽 / 複製摘要皆不得顯示 `Shock`。

---

## 23.9 V1 封版限制

Prototype V1 不再新增大功能。

若後續需要擴充，應由工程師依架構規劃 V1.1 / V2。

## 25.3 開發板運算可行性判斷

Prototype V1 功能以「狀態機 + 計時器 + 本機資料紀錄 + BLE 單案同步」為主，未納入雲端、GPS、錄音、病患個資、即時多人同步等高複雜功能。

因此，以 ESP32-S3 等級開發板進行 Prototype V1 驗證，功能範圍屬於合理可行。

工程實作時建議：

- 使用事件狀態機管理 OHCA / Training / 6秒通氣。
- 使用非阻塞式計時，避免倒數、蜂鳴器、LED、螢幕更新互相卡住。
- 螢幕採局部刷新，警報畫面才做全畫面切換。
- 案件資料以結構化 JSON 或等效資料格式保存。
- BLE 同步採單案整筆傳送，避免片段同步造成漏資料。
- 補登事件需與本機即時事件分開標記。
- Training 與 OHCA 共用核心狀態機，以參數區分 `case_mode` 與 `epi_interval_seconds`。
