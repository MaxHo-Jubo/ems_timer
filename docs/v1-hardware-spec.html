2主控與顯示
2.1　ESP32-S3（GOOUUU 開發板 / N16R8 模組）
項目規格來源
CPUXtensa LX7 32-bit 雙核，最高 240MHz📄
內建 SRAM512KB📄
Flash16MB（模組型號 N16R8 的「16」）📄
PSRAM8MB octal（八線）——本專案最重要的一條硬體限制，見下方警告🔬
無線Wi-Fi 2.4GHz b/g/n + Bluetooth 5（LE）；本專案只用 BLE，不開 Wi-Fi📄
USB晶片內建 USB-Serial/JTAG（走 GPIO 19/20）。韌體 Serial 走 USB-CDC，不佔用 UART0 的 GPIO 43/44🔬
板載 RGB LEDGPIO 48 出廠接 WS2812🔬
電源輸入板上絲印為 V5IN，即一般開發板的 VIN（同一條 5V 軌）🔬
韌體佔用Flash 使用率約 71%（Impl-Phase H 完成時快照）🔬
🔴 GPIO 35 / 36 / 37 不可當一般 I/O（2026-05-08 實機踩雷確認）：採購到的板子實際是 N16R8 octal PSRAM 模組（金屬遮蔽罩上印 ESP32-S3-N16R8），這三支腳內部給 PSRAM 用，一旦當 I/O 驅動就會 Guru Meditation StoreProhibited 當機。
→ 顯示器的 SPI MOSI／SCK 因此改用 GPIO 2／3，代價是 ADC1 三支腳（GPIO 1/2/3）全部用完。
→ 未來若能採購到標準 N8 模組，GPIO 35/36/37 才會釋出。下單時務必確認模組型號。
⚠️ 不可作 I/O 的腳位：GPIO 0 / 45 / 46（strapping，開機行為敏感）、GPIO 8~13（內建 SPI Flash）、GPIO 19 / 20（USB D-／D+）、GPIO 26~32（Flash bonding pad，保守禁用）、GPIO 35 / 36 / 37（本模組的 octal PSRAM）。
2.2　2.8 吋 TFT 顯示器（ST7789）
項目規格來源
驅動 ICST7789（此類模組常見為 ST7789V，本專案未拆殼核對版本）📄
面板2.8 吋 LCD，解析度 240×320（韌體橫置使用 = 320×240）🔬
色深16-bit RGB565📄
介面SPI 四線（CS / DC / RST / MOSI / SCK）；MISO 不接，韌體只寫不讀🔬
模組供電VCC 必須接 5V（V5IN）——模組板上自帶 LDO 與電平轉換，餵 3.3V 會 brown out🔬
訊號準位3.3V 邏輯直連即可，不需外加電平轉換（模組自帶）🔬
背光LED 腳接 3.3V 常亮，無 PWM 調光——原本要走 GPIO 1 的背光 PWM，該腳已改派給 TFT DC🔬
顯示極性此批紅板出廠 polarity 與函式庫預設相反，韌體必須呼叫 invertDisplay(false)🔬
繪圖函式庫LovyanGFX 1.2.x（sprite + DMA 整頁推送），全頁切換約 4ms🔬
外殼開孔顯示窗約 60×45mm（顯示區 50×38mm + PCB 外框餘裕）📄
⚠️ 函式庫踩雷紀錄：TFT_eSPI 2.5.43 對 ESP32-S3 SPI controller 做暫存器級存取，在此 N16R8 模組 init() 當下即 StoreProhibited 當機，換腳位無解。中途改用 Adafruit_ST7789 可跑但 CPU byte-swap 太慢，最終定案 LovyanGFX。
3電源鏈
🔋 電源拓樸：
Type-C 充電輸入 → TP4056 充電 → 電池（3.0~4.2V） → SX1308 升壓 5V → ESP32 V5IN ＋ TFT VCC
電量計掛在電池節點量電壓，不在升壓後量。
3.1　鋰電池（523450 LiPo 1000mAh）
項目規格來源
化學／電壓單節鋰聚合物 3.7V 標稱（工作區間約 3.0~4.2V）📄
容量1000mAh📄
尺寸5.2mm × 34mm × 50mm（外殼設計依此預留）🔬
保護板電池自帶（黃色 Kapton 膠帶下可見 DW01／8205A 小 PCB）：過充／過放／過流／短路🔬
接頭JST PH2.0 公頭，實測極性「左紅右黑」（接頭正面、卡榫朝上）🔬
🚨 PH2.0 接頭極性沒有業界標準，賣家文案不能信。每次接新電池／新模組前，一律先用電表量極性（紅棒讀正值那端才是 +）。
3.2　充電升壓一體模組（聯騰 MTARDTP4056S）
項目規格來源
充電 ICTP4056——單節鋰電池線性充電，4.2V 恆流／恆壓，本模組預設充電電流 1A（= 1C）📄
保護 ICDW01（過充／過放／過流偵測）＋ 8205A（雙 N-MOSFET 開關）📄
升壓 ICSX1308——DC-DC 升壓，電感 + 可調電位器輸出 5V📄
輸入USB Type-C🔬
輸出OUT+ / OUT- 焊盤，校壓到 5.00V ± 0.05V；帶 TFT 負載後不可掉到 4.7V 以下（否則 ESP32 brown-out 反覆重開）🔬
輸出電流上限規格頁未標示，推測約 1A，以實測為準⚠️
電池接點板上無 JST 座，B+／B- 為焊盤（需自行焊 PH2.0 母座）🔬
已知缺項無真正的 load-sharing（邊充邊用時電流路徑未分離）🔬
🚨 兩條會燒晶片／燒三週的規則：
① OUT+ 只能接 V5IN，絕不可接 3V3——接錯直接燒 ESP32。接線前用電表確認該腳對 GND 是 ~5V。
② OUT-（GND）這個接點必須焊死，不可用杜邦線／排針可拔插方式。此接點的接觸電阻會造成約 0.5V 的 GND 回流壓降（ground bounce），症狀是螢幕白屏而不是不開機，極易誤判成螢幕或韌體問題——這個坑 2026-06-14 定位、2026-07-04 才修復，花了近三週。焊死後實測通過。
4電量計：MAX17043（故障）→ MAX17048（未驗證）
🔴 本章是全份文件唯一「規格尚未成立」的部分。 MAX17048 是 2026-09-06 選定的換裝方案，模組尚未到貨、未上機、韌體換算常數還停在 MAX17043 的值、相關文件也還沒改。 下表的 MAX17048 欄位全部來自晶片與模組的公開規格，沒有任何一項經過本專案實測，不可當作已驗證事實引用。
4.1　兩顆晶片規格對照
項目MAX17043（現役・已故障）MAX17048（換裝方案）
演算法Maxim ModelGauge — 純電壓推估電量，不需要串聯電流檢測電阻，也不需要學習週期
I2C 位址0x36 🔬0x36（相同，韌體不用改位址）📄
電壓解析度12-bit A/D，1.25mV / LSB（資料在 bits 15:4）🔬16-bit，78.125µV / LSB 📄
電壓換算式mV = (raw >> 4) × 1.25 🔬mV = raw × 0.078125 ⚠️
電量（SOC）格式高位元組 = 整數 %，低位元組 = 1/256 %（兩顆相同，韌體這段不用改）
充放電速率暫存器❌ 無✅ 有（CRATE，本專案暫不使用）📄
晶片 VDD 上限4.5V 📄4.5V——模組 VIN 絕不可接 5V 📄
🚨 換型號一定要改的韌體常數：兩顆的電壓解析度差 16 倍。沿用 MAX17043 的 1.25mV/LSB 去讀 MAX17048，電壓會直接錯 16 倍。目前韌體 VCELL_SHIFT_BITS / VCELL_LSB_MV 兩個常數仍是 MAX17043 的值，尚未修改。
4.2　現役 MAX17043 的處置紀錄
日期事件結果
2026-08-22 上機驗收：I2C 0x36 連掃 5 輪無掉線；讀出 3.844V / 54.4%，對比電表 3.88V 差 36mV（在手持電表誤差帶內），確認量到的是真實電池電壓 通過
2026-09-06 發現模組是 V1.1 佈局：板上 2.2kΩ 上拉接的是電池電壓而非 3.3V，實測 I2C 兩線閒置電位約 4V，超過 ESP32-S3 輸入高準位上限 3.6V →「08-22 能跑」其實是超規狀態下的能跑 超規
2026-09-06 先修好麵包板地線（同一條 GND 插遠處讀 4~20Ω、插緊鄰 ESP32 GND 孔讀 0.4Ω），排除地線偏移假說後重測：每次讀 VCELL 都回 Error 263（逾時，晶片有回應自己的位址、之後抓住資料線不放），同一條 I2C 上的 DS3231 全程正常 判定故障
⚠️ 故障根因不明。焊接方式在 08-22 驗收前就存在故排除；候選只剩拔插時的 ESD 或瞬間反接，都無法證實。決策不依賴根因——逾時證據已足以判定更換。

5時間與 I2C 周邊
5.1　DS3231 即時時鐘模組
項目規格來源
晶片DS3231——內建溫度補償晶振（TCXO）的 I2C 即時時鐘📄
走時精度±2ppm（0~+40°C），約等於每月誤差 < 1 分鐘——這是選它而非一般 RTC 的理由（醫療紀錄可信度）📄
I2C 位址0x68🔬
附掛 EEPROM模組板上另有 AT24C32（32Kbit ≈ 4KB）EEPROM，位址 0x57，本專案未使用但會出現在 I2C 掃描結果🔬
備援電池CR2032 紐扣電池座（主電源斷電時保持走時）📄
韌體行為開機時偵測 0x68：在線 → 用硬體 RTC 當時間來源；不在線 → 降級成無 RTC 模式，靠 BLE 對時🔬
⚠️ 兩件尚未確認的事：
① CR2032 備援電池疑似沒電——2026-09-05 裸板測試時 RTC 回報的時間超出合理範圍而被韌體拒絕採用。換電池後需重測「對時 → 斷電 30 秒 → 重開仍記得時間」。
② 模組 VCC 走 3V3 是推定，非逐條驗證過的紀錄——專案文件只留下資料線（GPIO 42/41）的明確記載，供電走線是依 I2C 模組慣例推定。

6輸入與提示
6.1　按鍵 ×8
項目規格來源
型式無段自復位輕觸開關（single-action，按一下 = 一筆事件）📄
接法一端接 GPIO 走晶片內部上拉（INPUT_PULLUP），另一端共用 GND ——不需要外部電阻、不需要 VCC🔬
防彈跳韌體 80ms，按下與放開共用同一門檻（只擋按下緣會讓慢速重繪期間的彈跳穿透，造成一按兩響）🔬
擴充空間目前 8 鍵全走主控本體 GPIO，未使用 I/O 擴充晶片🔬
6.2　蜂鳴器
項目規格來源
型式主動式（內建振盪，給電即響，不需韌體產生頻率）📄
驅動GPIO 14 直接推（digitalWrite），GPIO 兼作供電，無獨立 VCC，另一端接 GND🔬
電流響起時峰值約 30mA（估算值，未實測）⚠️
6.3　板載 WS2812 RGB LED
項目規格來源
來源GOOUUU 開發板出廠自帶，接在 GPIO 48，非本專案採購🔬
目前用途韌體開機時寫入全暗把它關掉，不作狀態指示🔬
影響GPIO 48 因此不能當一般 I/O——訊號會被 LED 吃成色彩資料（TFT DC 原本規劃在此，實機發現 LED 狂亂閃後改到 GPIO 1）🔬
📌 產品規格書列的「LED 狀態燈」目前由這顆板載 LED 佔位，尚未實作狀態指示邏輯；量產時應改為外接指示燈並重新分配腳位。

8.1　同一支腳的互斥組合
衝突原因目前處置

8.2　實機踩過的坑（都不會在編譯期報錯）
  • 電池供電時螢幕白屏 — 根因是電源模組負極接點的接觸電阻造成約 0.5V 接地壓降；正極與升壓輸出量起來全正常，只有這個接點有問題。焊死該接點後解決，前後花了近三週。
  • 麵包板接地本身就是誤差來源 — 同一條地線插在遠處讀 4~20Ω，插在緊鄰主控 GND 腳的孔讀 0.4Ω。200mA 走 4Ω 就是 0.8V 偏移，足以讓 I2C 裝置把「低電位」判成「高電位」。所有周邊的 GND 一律星狀接到主控 GND 腳旁，不要串在電源軌上。
  • MAX17043 模組的上拉接電池電壓 — 該板型（V1.1）的 2.2kΩ 上拉接在電池節點，實測把 I2C 兩線閒置電位拉到約 4V，超過主控 3.6V 的輸入上限。「先前能跑」是超規下的能跑，不是設計正確。換用上拉接 VIN 的模組可解。
  • 顯示器函式庫對 ESP32-S3 做暫存器級存取會當機 — TFT_eSPI 在此模組初始化即當，換腳位無解，只能換函式庫。
  • 開機前 1~2 秒的除錯訊息會被吃掉 — USB 需要時間列舉完成，開機最前面印的訊息主機收不到；重要訊息要印在初始化結尾。
🚨 接線通則（每次動硬體都適用）：
① 接電池／模組前先量極性　② 先接電源與地、再接訊號線　③ 每量一次電壓都要記錄黑棒接在哪裡（否則兩次量測互相矛盾時無從判斷）　④ 新模組先單獨供電量過再接上主控，把接錯的代價封頂在那顆晶片上。
