4MCP23017 規格與接線

為何選已焊排針版

PM 強項是韌體，硬體弱項。選已焊排針版省下「焊 28 隻 pin」的工，到貨直接插麵包板。

接線（接到 SparkFun Thing Plus-ESP32-S3 的 Qwiic I2C）

MCP23017 pinESP32-S3備註
VDD (9)→3V3
VSS (10)→GND
SDA (13)→GPIO 8（Qwiic SDA）Wire bus 共用
SCL (12)→GPIO 9（Qwiic SCL）同上
RESET (18)→3V3不可浮接
A0/A1/A2 (15/16/17)→GND × 3I2C 位址 = 0x20
INTA (20)→任一 GPIO5 顆按鈕中斷通知，省 polling
I2C pull-up：Qwiic bus 已有 2.2kΩ 板載；走麵包板裸接時 SDA/SCL 各加 4.7kΩ pull-up 到 3V3。

I2C 位址表（避衝突確認）

裝置位址來源
MCP230170x20新採購
MAX17048 燃料計0x36SparkFun 板載
SH1106 OLED0x3C現行
DS3231 RTC（Dev-Phase 3）0x68預留
✅ 無衝突。

7收貨驗收 SOP

7.1 電池（共用兩條路徑）

到貨當天執行，對齊 PM #5「接前驗極性」：

驗收步驟
  1. 三用電表量極性：紅探針碰電池接頭一邊、黑探針碰另一邊，讀數正值 = 紅探針那邊是 +。確認紅線 = +、黑線 = -。
  2. 驗保護板：短路兩極 < 0.5 秒，保護板應自動斷開（不會冒煙）。
  3. 量電壓：3.6~4.2V 之間（出廠半電狀態）。
  4. 外觀：無膨脹、無漏液、無破損。
⚠️ PH2.0 接頭極性沒有業界標準，賣家文案「左紅右黑」不能信，必須量。如果極性對不上接收端模組，拆 JST 接頭塑膠外殼（小一字起子撥開卡榫）把紅黑線交換重插。

7.2 電池模組（路徑 A — PowerBoost 1000 C）

依 docs/power-module-purchase.md §4.2 既有 SOP 執行：

  • 升壓電壓校正到 5.00V（PowerBoost 1000 C 出廠 5.2V，可接受不必校）
  • USB 插拔測試 pass-through
  • 充電電流確認

7.3 開發板+電池模組（路徑 B — SparkFun Thing Plus-ESP32-S3）

驗收步驟
  1. USB-C 插上電腦：ESP32-S3 應自動進入 USB DFU 模式，可被 esptool 偵測。
  2. 接上 LiPo 電池：MAX17048 燃料計應透過 I2C 0x36 回傳電量。
  3. Qwiic 接頭量測 SDA/SCL 對 3.3V 應有 2.2kΩ pull-up。
  4. 板載 microSD 卡槽插卡測試讀寫。

7.4 MCP23017 DIP-28

驗收步驟
  1. 麵包板插好，VDD/VSS 接 3V3/GND。
  2. SDA/SCL 接 ESP32 I2C。
  3. RESET 接 3V3（這步漏掉會狂 reset）。
  4. A0/A1/A2 接 GND（位址 0x20）。
  5. 跑 I2C scanner sketch，應在 0x20 看到回應。

7.5 排針

無特殊驗收，焊接時注意對齊 90 度即可。

11採購建議

🎯 短期決策（Dev-Phase 2 BLE 開發）— 走路徑 A
下單清單：
  • 電池 ×1（蝦皮 ↗）
  • 電池模組 PowerBoost 1000 C ×1（露天 ↗）
  • MCP23017 已焊版 ×1（蝦皮 ↗）— 為未來預留，現階段不接也行
  • 排針 ×1 包（蝦皮 ↗）
理由：
  1. 路徑 A 完全符合 PM 6 條（除了 #3 接口非 Type-C，可接受）
  2. 韌體 0 行改動，95 個現有 test 全綠狀態保留
  3. Dev-Phase 2 真正要做的是 BLE 通訊，不該為了硬體換板打斷節奏
  4. MCP23017 提早採購備料，等 Prod-Phase 真要切 SparkFun 時不用等貨
🔮 中長期決策（Prod-Phase pilot）— 再評估路徑 B

當以下條件之一成立時觸發：

  • Dev-Phase 1.5 INMP441 + microSD 整合驗證後，發現 SD 卡 OTA 是必要功能
  • 外殼設計確定要小體積（< 60×40×20mm），GOOUUU 太大放不下
  • Prod-Phase pilot 量 5~10 台，整合度成為主要考量

切換時的工作清單：

  • 路徑 B 採購（再下單一次 SparkFun Thing Plus-ESP32-S3）
  • GPIO allocation 重編
  • Button 抽象層重構
  • 95 unit tests 全部重跑
  • 實機重新驗證 Dev-Phase 1 全項目
