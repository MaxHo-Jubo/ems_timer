自動化測試怎麼做的
  1. 啟動瀏覽器自動化工具開啟線上 demo。
  2. 透過 demo 內建的畫面切換函式逐一切到 34 個畫面（含 dialog、子選單、補登流程等）。
  3. 對每個畫面所有可見文字元素做位置計算，比對是否超出 320×240 模擬螢幕邊界。
  4. 自動截圖溢出的畫面供比對。
  5. 修完後重跑同一套測試，確認 34/34 都通過。
過程中遇到並解決的問題
  • 第一輪修完還剩 OHCA 案件總覽 5 像素溢出 — 字級從 14 縮到 13、行高拉緊，剛好塞進 224 像素可用區域。
  • 事件時間軸事件多時一頁塞不下 — 加上下翻頁機制，每頁顯示 7 列，標題旁顯示頁碼如 (1-7/9)，▲▼ 捲動。
  • 對話框（重置訓練 / 刪除紀錄 / 恢復預設）三個畫面結構雷同 — 抽出共用樣式「對話框三段釘底版面」，標題、內文、操作提示各自定位，未來新增對話框直接套用。
  • 主選單 5 項邊緣切 2px — 把每列高度從 30px 微縮到 28px，現在留有 17px 安全帶。

  3. 子選單底部提示重排：以前「上下選擇　主鍵確認　返回取消」全擠在中間、左右會被切；現在改成左 / 中 / 右三段分排，貼邊 10 像素，視覺更清楚也不再溢出。
  4. 內部進度標籤對齊現況：程式碼開頭的階段註解全面重寫，把已落地的補登 / 總覽 / Amio 等子流程標為 ✅；把因升級螢幕而被佔用的腳位（震動馬達讓位給彩色螢幕）也註明清楚。
過程中遇到並解決的問題
  • 第一次修「Amiodarone 已紀錄」只降一級字仍然爆字 — 增開更小一級的字級檔位專供英文+中文混合的長標題使用。
  • 補登次數第一版只把大數字下移避免擋到「次數(1~5)」標籤 — PM 回饋「跟 demo 不一樣」，第二版整個改成清單樣式對齊 demo。
  • 子選單底部三段提示縮字仍擠 — 改成三段分別貼左 / 置中 / 貼右，字級縮 0.85 倍，邊距留 10 像素。
  • 程式碼註解一度誤寫「× 改 ASCII x 避免字型缺失」— 實機驗證字型有 ×，且 Amio 確認 / 補登成功畫面也已用 ×，改回 × 並修正註解一致性。
  • 線上 demo 主選單原本只能看到 4 個項目（第 5 個「系統設定」被螢幕底邊切掉）— 已修，把每列高度從 48px 縮成 38px，5 項合計 217px 在 240px 螢幕內完整顯示。
